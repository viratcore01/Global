# Global Cinema Opportunity Radar

A personal, self-hosted system for **discovering, filtering, ranking and tracking**
acting / casting / festival / crew opportunities.

It is not a job board. It watches the sources you choose (email, RSS, sitemaps,
public Telegram channels, listing pages), extracts opportunities **deterministically
first**, vetoes scams and ineligible calls, ranks what remains against your own
profile, and pushes only the good stuff to your phone with Apply / Ignore / Scam
buttons.

- **No paid service required.** The whole pipeline runs locally with SQLite.
- **No auto-applying.** Every application is your decision.
- **No scraping of login-only, private, CAPTCHA-protected or bot-forbidden pages.**

---

## Quick start

Requires Python 3.10+ (tested on 3.12 and 3.15).

```bash
python -m venv .venv
# Windows: .venv\Scripts\activate
source .venv/bin/activate
pip install -r requirements.txt          # add -r requirements-optional.txt for extras

cp .env.example .env                      # Windows: copy .env.example .env (optional)
python -m radar init --demo               # dirs, database, reply secret, demo data
python -m radar doctor                    # validate config, DB, optional extras
python -m radar opportunities             # see the seeded demo opportunities
python -m radar serve                     # read-only dashboard on :8501 (needs streamlit)
```

`init --demo` loads local fixtures only — no network, no accounts. Use it to see the
whole flow end to end before touching real sources.

### Point it at your life

1. Edit [`config/profile.yaml`](config/profile.yaml): age range, city, travel radius,
   languages, role types, nudity limit, paid-only, fee tolerance.
2. Add hand-vetted sources to [`config/sources.yaml`](config/sources.yaml). Everything
   ships disabled on purpose. See [docs/SOURCES.md](docs/SOURCES.md).
3. Fill `.env`: `NTFY_TOPIC`, `NTFY_REPLY_TOPIC`, `RADAR_REPLY_SECRET` (generated by
   `init`), and `IMAP_*` if you want the email inbox source.
4. Run `python -m radar doctor` again, then `python -m radar run --force`.

## How it works

```
sources ──► discovery ──► raw store ──► extraction ──► dedup/cluster
                                                          │
                        alerts ◄── ranking ◄── eligibility + vetoes
                          │
                    ntfy buttons ──► reply listener ──► labels ──► learning
```

| Stage | What it does |
| --- | --- |
| **Discovery** | RSS/Atom, sitemap diffing, public Telegram previews, IMAP email, Google Alerts, SearXNG, listing pages, Wayback CDX, optional Discord. All URLs go through one queue. |
| **Fetch** | Honest bot User-Agent, robots.txt + Crawl-delay, per-domain token bucket, retries with jitter, size limits. `curl_cffi` / Playwright are optional escalations. |
| **Extraction** | extruct (JSON-LD / microdata / OpenGraph), config-driven CSS/XPath, trafilatura main text, then deterministic heuristics for deadline, city, pay, age, gender, language, contact, fee, nudity, rights, shoot window. Every field keeps an evidence span. |
| **AI (optional)** | An LLM only fills *gaps* with strict JSON, no tools, span-verified output. The system works fully without it. |
| **Dedup** | Canonical URLs, SHA-256 exact match, MinHash LSH near-duplicates, structured fuzzy keys. Clusters are kept, never deleted. |
| **Decision** | Hard vetoes (expired, pay-to-apply, guaranteed role, paid portfolio, group funnel, reputation, perpetual buyout...) → eligibility gate against your profile → risk penalties → weighted score (embedding 35 / BM25 25 / trust 20 / urgency 10 / completeness 10). |
| **Alerts** | Instant when score ≥ 80, complete and clean; quiet hours 23:00–07:00 IST; daily cap; 08:00 digest otherwise. The 80/55 cut-offs come from `config/profile.yaml` unless `RADAR_INSTANT_THRESHOLD` / `RADAR_DIGEST_THRESHOLD` override them. Buttons are HMAC-signed and answered over a private ntfy reply topic, so no inbound port. |
| **Learning** | Every label stores a feature snapshot; after 100 labels a logistic-regression model replaces the cold-start weights. Weekly metrics, precision@15, recall audit. |

See [ARCHITECTURE.md](ARCHITECTURE.md) for the component map and
[Global_Cinema_Opportunity_Radar_Final_Report.md](Global_Cinema_Opportunity_Radar_Final_Report.md)
for the original design rationale.

## CLI

```
python -m radar <command>
```

| Command | Purpose |
| --- | --- |
| `init [--demo]` | Create dirs, DB, reply secret; optionally load fixtures |
| `doctor` | Config, DB, FTS, source and optional-extra checks |
| `config` | Print effective config (secrets redacted) |
| `sources [list\|enable\|disable\|sync] [name]` | Manage the source list |
| `discover [--force] [--source NAME] [--limit N]` | Run discovery adapters, enqueue URLs |
| `ingest [URL] [--limit N] [--llm]` | Process the queue (or a single URL) |
| `run [--force] [--digest] [--llm]` | One full cycle: discover → ingest → score → alert |
| `worker [--once] [--force JOB]` | Long-running scheduler + reply/IMAP listeners |
| `score [ID] [--rescore] [--llm]` | Score pending or one opportunity |
| `digest [--dry-run]` | Send or preview the daily digest |
| `alerts [--limit N]` | Alert history |
| `opportunities [--status] [--min-score] [--city] [--q] [--risk-only]` | List/search |
| `show ID` | Full detail plus cluster sources |
| `label ID apply\|ignore\|scam\|replied\|booked\|archive\|undo [--note]` | Record an outcome |
| `replay --raw-id N \| --queue-id N [--llm]` | Re-extract a stored document |
| `quarantine [list\|resolve] [ID]` | Inspect or resolve failed extractions |
| `health` | DB, queue, sources, jobs, disk |
| `metrics [--days N]` | Precision, outcomes, scam metrics |
| `audit [--sample N]` | Sample vetoed/low-ranked items for recall |
| `weekly [--force]` | Weekly report + model refit |
| `refit [--clear]` | Refit or reset the learned model |
| `backup [snapshot\|list\|verify\|restore] [PATH]` | SQLite `.backup` snapshots |
| `reply [--once]` | Poll ntfy action replies |
| `imap [--once]` | Poll or IDLE the mailbox |
| `serve [--port N]` | Launch the Streamlit dashboard |
| `version` | Print version |

Every command that prints a report also accepts `--json` for machine-readable output.

## Alerts

ntfy is the notification channel because it needs no inbound port, supports signed
HTTP actions and works on Android/iOS/desktop.

1. Install the ntfy app and subscribe to a long random topic.
2. Set `NTFY_SERVER`, `NTFY_TOPIC` and `NTFY_REPLY_TOPIC` in `.env`.
3. `RADAR_REPLY_SECRET` signs every Apply / Ignore / Scam payload; the reply
   listener verifies it before touching the database.
4. Run `python -m radar reply` (or the worker, which runs it for you).

A digest looks like a short priority-ordered list; an instant alert is one
opportunity with deadline, pay, city, risk/safety notes, evidence and buttons.
Set `RADAR_DASHBOARD_URL` to a reachable address (Tailscale/VPN) and the digest
ends with a link back to the dashboard.

## Tests

```bash
python -m pytest
```

The suite covers URL normalisation, date parsing (including Hindi/Hinglish),
evidence grounding, extraction fixtures, vetoes, eligibility, dedup, scoring,
config, database, backup/restore, the fetch layer (robots, retries, SSRF guard,
size cap — via a mock transport), scheduler due-times, CLI smoke tests and an
end-to-end fixture → alert → label flow. No network access is required.

## Safety and limits

- Never pay to apply. The system vetoes known pay-to-apply patterns, but it is a
  filter, not a guarantee — read the [SECURITY.md](SECURITY.md) checklist.
- Festival entry fees are **not** scams; they are stored as `fee_required` and shown.
- The radar cannot verify a person's identity. Verify the production, the contact
  and the venue independently before you travel.
- Social platforms (Instagram/Facebook/X/LinkedIn/TikTok) are deliberately out of
  scope: their terms and anti-bot measures make them fragile and hostile.
- An untested backup is not a backup. Run `python -m radar backup verify` monthly.
